One commit or none

The transfer row, both ledger entries, both cached balances and the audit row commit together. The 4 invariants hold across every row, checked by an @AfterEach on every money-moving test.

The fraud branch is a no-op on the ledger

A score at or above 0.85 returns 422 BLOCKED_FRAUD, writes an audit row, and posts nothing. The block path is auditable even though the model behind it should not decide anything.

Balances rebuild from the ledger

GET /reconciliation recomputes every balance as opening balance plus the signed entries. Across a load run it rebuilt 100 accounts from 113,046 entries with zero drift.

Notes

The @Version optimistic lock stops the overdraft.

In the 50-thread race, exactly 25 post and 25 fail with INSUFFICIENT_FUNDS, and the source lands on 0.00.

One UNIQUE(idempotency_key) index closes the retry window.

20 duplicate requests write 1 transfer, so 25.00 moves rather than 500.00.

The fraud model ships broken on purpose, AUPRC 0.0041.

It demonstrates the inline scoring and audited block path without deciding anything.
