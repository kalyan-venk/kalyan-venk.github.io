Product Compass

Data Pipelines and Analytics for AI Developer Tools

Public issue reports contain useful clues about where a product gets in the way of its users. Product Compass turns those reports into a reliable dataset for investigating the problems behind them, starting with OpenAI Codex.

What the pipeline does

  • Collects GitHub issues through a Python workflow with date filters, pagination and request pacing. Saves the source records with collection metadata so the analysis can be traced back to its inputs.
  • Loads records into PostgreSQL and refreshes existing issue IDs without duplicates. Preserves source links, timestamps and labels, with all 14 mapped fields reconciled against the saved JSON.
  • Summarizes issues by creation date, state and label to support operational investigation. Keeps overlapping labels separate from counts of distinct reports or affected users.

The data question

Did we collect the records we intended to collect, preserve their meaning and load them correctly? The pipeline checks completeness signals, keeps unique issue IDs and reconciles database values with the source snapshot.

The operations question

Which reported problem deserves investigation next? Report frequency is one signal alongside severity, ongoing exposure and available workarounds. The descriptions provide context that a label count alone cannot.

First verified snapshot

Collected November 14, 2026 for issues created November 1–7 in UTC. The dataset contains 1,052 open and 107 closed issues, with no pull requests.

These are public reports, not the complete customer-support queue. Labels overlap and a closed issue does not necessarily mean a fixed problem. Upserts retain current values rather than a history of changes.
